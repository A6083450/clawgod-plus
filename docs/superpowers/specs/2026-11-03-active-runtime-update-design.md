# 活跃进程下原地升级

## 目标与约束

用户要求有 Claude 进程时也能升级，并明确升级成功后不需要保留旧版本。采用原地升级，不主动终止进程，不承诺旧会话继续正常工作。仅修改仓库代码和隔离测试，不安装到本机，不提交或发布。

## 方案

- 新旧运行时并存：可保护旧会话的延迟加载，但需要版本目录和生命周期管理；用户选择成功后不保留旧版本，不采用。
- 警告后原地升级：复用已有事务，成功清理旧运行时快照，失败恢复；采用此最小方案。仍运行的会话可能在后续加载模块时失败，必须在提示及文档中说明。

## 行为

共享 acquireRuntime 默认仍拒绝活跃进程；安装、更新（含 --no-upgrade）和重补丁显式允许活跃进程并向 stderr 警告。卸载仍拒绝活跃进程。维护锁、锁校验、进程扫描失败时停止、维护期阻止新会话、候选启动检查和失败回滚保持不变。不增加用户开关或依赖，不删除当前版本所需 clean-source 备份，不清除未确认安全的历史恢复事务。Windows 本次事务若因占用或权限无法清理，明确提示安装/恢复结果与待清理路径，不强杀进程，不将残留误认为回滚失败，也不谎报旧版本已删除。

## 验证

隔离真实子进程验证允许升级且不杀进程，升级期间拒绝第二个写入者及新会话，卸载仍拒绝；验证 Unix/Windows 安装入口传递允许策略。运行已有事务成功清理、失败回滚测试，重生成并检查 dist。原生 Windows 无可用 PowerShell 时明确报告未验证。
